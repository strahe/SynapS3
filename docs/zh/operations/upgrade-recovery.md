# 备份与恢复

把数据库、缓存和对应程序作为同一恢复点保护。重试后台工作前，先恢复失效的依赖。

## 备份运行数据

创建备份前，停止新的 S3 流量和 SynapS3。数据库、缓存、配置、凭据和对应程序必须一同保留。备份和验证步骤见[运行数据](../configuration/runtime-data.md)。

## 重启后验证

启动后运行：

```bash
curl http://127.0.0.1:9090/healthz
synaps3 admin settings get
synaps3 admin task stats
```

预期结果：健康状态为 `ok`，生效设置与部署一致，后台工作继续且没有意外失败。恢复正常流量前，通过 S3 API 读取一个已知对象。

## 数据库不兼容时

停止 SynapS3，确认配置的数据库是预期目标。原样保留数据库和匹配缓存。将经过验证的备份恢复到独立的空数据库和运行目录，并使用该恢复点保存的程序启动。具体步骤见[恢复顺序](../configuration/runtime-data.md#恢复顺序)。不要修改保留的数据来绕过兼容性检查。

SynapS3 不会修改不兼容的数据库。

使用空数据库启动会初始化独立记录，不会导入备份中的存储桶、对象、用户、任务或钱包操作，也不会删除远端数据集或停止其存储费用。不要让独立的操作账本并行控制同一个钱包。

## 恢复后台工作

重启后，未完成的工作会自动恢复处理。

- 使用 **Retry** 恢复已停止的任务。任务列表按结果显示重试资格，打开详情后再检查当前条件。如果其他操作已接管，或恢复不安全，Retry 会说明原因并刷新列表。
- 从存储桶的 **Storage** 标签页恢复存储提供方替换。
- 存储传输任务因内部错误停止时仍可重试。重试会先检查上一次已经完成的部分，再继续。
- 钱包操作在尚未发出广播、或因内部错误停止时，可以从 Tasks 重试。重试会先核对这笔操作：从未广播过时才会发出交易，否则只检查已经发出的交易。如果广播可能已经发出、却没有记录到交易，操作会被标为结果未知，不能再重试。
- **Retry** 会先检查存储提供方是否已有分片；确认缺失后才重新上传。重传可能增加带宽用量或开启另一次上传会话。
- 确认将失败移入 **Closed**；用 `scope=history&status=failed` 查看。
- 批次恢复会保留已签名请求，并在再次提交前检查链上结果。缺失的分片会在安全时重新传输。存储提供方错误和传输失败使用有限预算。批次明确被拒绝且链上核实未落地时，无法恢复的分片不会阻止其余分片继续提交。恢复停止后，批次会保留已有证据。在 **Tasks**（Submit batch、Failed）中或通过 `synaps3 admin storage-confirmation list` 找到它，恢复依赖后使用 **Retry**。已被接受的请求如果与链上证据冲突，会继续停止并等待核查。
- Pull 队列已满时，会按存储提供方要求的延迟再次尝试，不消耗重试预算。其他 Pull 失败最多使用 12 次机会。重启不重置已用次数；手动 Retry 使用新的预算。

常用命令：

```bash
synaps3 admin task list --status failed --limit 100
synaps3 admin task stats
synaps3 admin task retry 42
synaps3 admin task acknowledge 42
synaps3 admin storage-confirmation list
synaps3 admin settings get
```

重试前先恢复失效的依赖。使用仪表盘、Admin API 或 CLI 操作，不要直接修改应用数据库。

## 恢复矩阵

| 场景 | 恢复方式 |
| --- | --- |
| 存储提供方或 RPC 暂时不可用 | 恢复连接。等待中的工作会自动继续；只重试标记为可重试的失败任务。 |
| 数据库空间不足 | 停止流量，释放空间或扩容数据库，再检查健康状态。 |
| 缓存磁盘空间不足 | 扩容磁盘、提高 `cache.max_size_gb`，或恢复远端存储与缓存清理进度。 |
| 需要迁离存储提供方 | 打开存储桶的 **Storage** 标签页，在 **Data sets** 中替换存储提供方。不要从 Tasks 重试替换。 |
| 进程崩溃 | 重启 SynapS3，验证健康状态和任务统计，再重试已停止的批次，并核对钱包结果。 |
| 启动时报告数据库不兼容 | 停止进程，确认配置的数据库是预期目标，原样保留数据库和匹配缓存，再按[数据库不兼容时](#数据库不兼容时)处理。 |

## 恢复备份

1. 停止 S3 流量和 SynapS3。
2. 验证备份校验和，选择同一恢复点的数据库和缓存产物。
3. 将数据库原生备份恢复到独立的空数据库，再将匹配的配置和缓存数据恢复到独立的空运行目录。
4. 使用该恢复点保存的程序。
5. 启动 SynapS3，然后检查 `/healthz`、生效设置、任务统计、failed 任务、钱包准备状态和已知 S3 对象。

这些检查全部通过前，不要恢复正常流量。
